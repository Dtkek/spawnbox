# Spawnbox

**Краткое описание:** Личный хостинг Minecraft по типу Aternos для ПК на Windows: панель ставит и запускает сервер, усыпляет его, когда все вышли, и будит, когда кто-то заходит. Друзья запускают сервер сами по коду доступа, играть можно с лицензией и без.

---

## 1. О проекте

### 1.1 Основная информация

- **Тип проекта:** Инструмент для личного использования (для Миши и друзей)
- **Стадия:** MVP
- **Дата начала:** 2026-11-04
- **Команда:** 1 человек
- **Бюджет:** нет, работает на своём ПК

### 1.2 Цели проекта

**Главная цель:** Поднять сервер Minecraft для друзей за пару кликов, без очереди и ручной настройки, чтобы запустить его мог любой, кому выдан доступ.

**Ключевые метрики:**
- От запуска панели до работающего сервера — выбор версии и две кнопки
- Друг запускает сервер без участия владельца
- Пока никто не играет, сервер не занимает память
- Мир можно восстановить из бэкапа в один клик

### 1.3 Проблема и решение

**Проблема:** На бесплатных хостингах есть очереди и ограничения, а ручная настройка сервера требует возни с Java, версиями и бэкапами.

**Решение:** Панель на Python сама скачивает ядро и нужную Java, управляет процессом сервера и делает бэкапы. Перед сервером стоит шлюз, который понимает протокол Minecraft: он отвечает за спящий сервер и будит его при входе игрока.

**Альтернативы:**
- Aternos и подобные — ничего не надо ставить, но очередь и чужие правила.
- Pterodactyl, Crafty — мощнее, но тяжелее в установке и избыточны для одного сервера.
- Аренда VPS — работает круглосуточно, но стоит денег.

## 3. Контекст и важные детали

### 3.1 Технический стек

- Python 3.11+, только стандартная библиотека: `http.server` для панелей, `asyncio` для шлюза
- Сборка: GitHub Actions и PyInstaller собирают один `spawnbox.exe` и обновляют релиз `latest`. Для загрузки workflow токену `gh` нужно право `workflow`. Данные exe лежат в `%LOCALAPPDATA%\Spawnbox`
- Фронтенд: `app/spawnbox/static/admin.html` и `guest.html`, без библиотек
- HTTP-запросы наружу — через `curl` (есть в Windows 10/11 и macOS): у Python 3.14 на Mac не проходит проверка сертификатов
- Ядра: Vanilla (Mojang), Paper (fill.papermc.io), Fabric (meta.fabricmc.net), Forge (maven.minecraftforge.net), NeoForge (maven.neoforged.net)
- Java: Temurin (api.adoptium.net), версия берётся из манифеста Mojang
- Для игроков без лицензии с Modrinth: AuthMeReloaded и SkinsRestorer на Paper, EasyAuth и Fabric API на Fabric

### 3.2 Ключевые особенности

- Все материалы и комментарии в коде — на русском (`project_language: Russian`).
- Три порта: шлюз `25565` (игра, наружу), страница для друзей `8766` (наружу), админка `8765` (только `127.0.0.1`). Сам сервер слушает `127.0.0.1:25566`, поэтому все игроки проходят через шлюз, и он точно знает, сколько их.
- На странице для друзей доступно только «посмотреть статус» и «запустить». Плагины, консоль и файлы дают полный контроль над ПК, поэтому они есть только в админке.
- По умолчанию код для запуска не нужен (`open_start`): Миша попросил, чтобы мир мог запустить любой. Это отключается на вкладке доступа.
- Импорт (`importer.py`) определяет ядро по настройкам CurseForge и Prism, файлам версий лаунчера и описаниям модов; клиентские моды — по описанию, данным Modrinth и имени файла. Исходные файлы только читаются.
- Код доступа личный, в конфиге хранится его SHA-256, и его можно отозвать. Код передаётся заголовком, поэтому чужой сайт не может отправить запрос от имени друга.
- Админка проверяет заголовки Host и `X-Spawnbox`, чтобы посторонний сайт в браузере владельца не мог ею управлять.
- Туннель нельзя направлять на порт админки: для неё все запросы из туннеля выглядели бы как локальные.
- EULA Minecraft принимает сам владелец в панели: без этого сервер не запустится, автоматически она не принимается.
- Если включён белый список, разбудить сервер входом в игру могут только игроки из него.

### 3.3 Ограничения и риски

**Ограничения:**
- Сервер доступен, только пока ПК включён. Панель не даёт ему уснуть, но выключить его можно обычным образом.
- Для друзей вне домашней сети нужен туннель или проброс порта — настраивается отдельно.
- За шлюзом все игроки выглядят как `127.0.0.1`, поэтому бан по IP не работает. Бан по нику работает.
- Одновременно работает один сервер.
- Разработка идёт на Mac: логика и тесты проверяются там, на самой Windows код нужно проверять отдельно.

**Риски:**
- При `online-mode=false` любой может зайти под чужим ником → AuthMe на Paper, EasyAuth на Fabric. На Vanilla, Forge и NeoForge пароля нет, там нужен белый список, а панель показывает предупреждение.
- Сервер на чужой сборке может не запуститься из-за мода, который панель не распознала → смотреть консоль, мир хранится отдельной копией.
- При смене `online-mode` у игроков меняется UUID, и инвентарь не переносится → выбирать режим до начала игры.
- Страница для друзей идёт по HTTP, код можно перехватить → код даёт только запуск сервера и отзывается в панели.
- Плагины и моды — это чужой код на ПК → ставить только из проверенных источников.

## 5. История изменений

### 2026-11-04 — Импорт своей сборки и запуск без кода

У Миши есть мир с большой сборкой на Fabric 1.20.1, и запускать его должен мочь любой. Добавлены импорт сборки и мира, NeoForge, установка точной версии ядра, EasyAuth на Fabric и запуск без кода. Время на сохранение при остановке выросло с 90 секунд до 10 минут, чтобы не повредить большой мир.

### 2026-11-04 — Репозиторий и один exe без Python

Код загружен в закрытый репозиторий. Сначала был архив с портативным Python, но Миша попросил обойтись без zip, поэтому теперь Actions собирает один `spawnbox.exe`. Заодно Actions прогоняет тесты и проверку exe на настоящей Windows.

### 2026-11-04 — Проект создан

Начало работы. Сначала проект задумывался для Mac, но Миша уточнил требования: ПК на Windows, запускать может любой, кому выдан доступ, играть можно с лицензией и без. Поэтому страница для друзей вынесена на отдельный порт с кодами доступа, а `online-mode=false` стал значением по умолчанию вместе с входом по паролю.
